# Limitations

Read this before drawing any conclusion from the numbers.

## 1. The data is synthetic

Every meteorological field is generated by a toy model. It reproduces the
*structure* of the problem — a monsoon trough, moving lows, orographic rainfall,
irreducible convective noise, model bias — but it is not the atmosphere.

Known ways the sandbox is easier than reality:

- **Spread–error correlation is ~0.7**, against roughly 0.3–0.5 in real ensembles.
  The ensemble is a better predictor of error here than it would be operationally.
- **Error growth with lead is too weak.** Precipitation MAE grows only from
  0.80 mm/day at D1 to 1.27 at D10; real medium-range error grows far more.
- **The truth is exact.** Observation uncertainty is zero by construction, so the
  data-uncertainty term of the decomposition is empty. With IMD gauges, IMERG
  retrievals or ERA5 this term is large, spatially varying, and would itself
  cause apparent "busts".
- **One NWP system.** No multi-model disagreement feature is possible; with TIGGE
  (ECMWF, NCEP, UKMO, JMA, CMC) it would be.
- **Idealised orography**, not a real DEM.

Implication: **transfer of the reported skill to real forecasts should not be
assumed.** The pipeline is what transfers; the numbers are not.

## 2. Model limitations

- Gradient boosting does not beat logistic regression or random forest here
  (PR-AUC 0.505 vs 0.522 / 0.525). A validation sweep of three configurations
  found no separation. The extra complexity is currently unjustified.
- **Recall at the 0.5 threshold is low (0.24–0.28).** As a screening tool the
  ranking (PR-AUC, ROC-AUC) is what matters; a lower operating threshold should
  be chosen per user and is not yet exposed in the UI.
- **Western disturbances are a failure case:** PR-AUC 0.30 and recall 0.005
  against a 24% base rate. The system is close to useless for that regime and
  says so on the model page.
- Quiet, dry situations have PR-AUC 0.197 — but a base rate of 3.8%, so the
  practical cost is low.

## 3. Scope limitations

- 1.0° grid in the sandbox. The architecture targets 0.25°; compute at that
  resolution is roughly 16× and has not been exercised.
- Regions are coarse bounding boxes, **not** official IMD meteorological
  subdivisions. Swap in a subdivision polygon file for operational use.
- The regime classifier is rule-assisted and **unvalidated against any
  independent event database**. No classification accuracy is claimed.
- The uncertainty "decomposition" is a set of named indicators reported side by
  side. It is not a formal epistemic/aleatoric variance decomposition and does
  not sum to a total.
- Model-attribution uses group occlusion (replace a feature block with training
  medians and re-run), not SHAP. It is exact for the model as evaluated but is a
  group-level, not per-feature, attribution.
- No spatial deep learning (CNN/ConvLSTM). With 207k training rows and one CPU
  core this was not justified; the ablation shows the tabular features are not
  yet saturated.

## 4. Operational caveats

- Confidence is `100 × (1 − bust probability)`. It is **not** a probability that
  the forecast is correct, and the band labels are UI conventions.
- Live ingestion is implemented but has never been executed against a live
  endpoint from this environment.
- No authentication. Rate limiting is a simple in-process counter, adequate for a
  prototype and not for a public deployment.
